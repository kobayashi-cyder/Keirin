# レース前特徴量データの受入規格（予測AI構築の前提）

## 現状（2026-11-08）
リポジトリにある `exports/results_3rentan.csv` は**レース終了後の確定着順・払戻**です。`exports/odds_3rentan.csv` は**限定的な買い目別オッズ**であり、全レースの締切前予測用データではありません。これらを混同して「AI学習済み」と主張しません。

実際に学習するには、レース前に公開されていた選手ごとの特徴量が必要です。本変更はその**データ整備の検査**で、学習済みAIはまだ実装していません。原データを公開する権利も含め、先に提供元の許諾を確認してください。

## 検査コマンド（Windows）

`Keirin-main` 直下で実行：

```cmd
py -3 tools\pre_race_readiness.py --output reports\pre_race_readiness_local.json
```

既定ファイル `data/pre_race_features.csv` が存在しない場合は `NOT_READY`、終了コード2となります。これは**予測に必要なレース前情報がない**という正しい診断です。ファイルを仮データで埋めたり、結果から過去に遡って生成しないでください。

検査テスト：

```cmd
py -3 -m unittest discover -s tests -p "test_pre_race_readiness.py" -v
```

## 入力CSVの各列

**1行＝1レースの1車番、1レースに7〜9行**。最低限以下の全列が必要です。

| 列 | 説明 |
|---|---|
| `race_id` | `exports/results_3rentan.csv` の `race_id` と一致 |
| `race_date` | 現地開催日 `YYYY-MM-DD` |
| `car_no` | 車番 1〜7、1〜8、または1〜9（レース内で重複なし） |
| `observed_at_jst` | 情報の実際の観測時刻。オフセット `+09:00` 付き |
| `deadline_at_jst` | 賭式の締切時刻。オフセット必須 |
| `start_at_jst` | 発走時刻。オフセット必須 |
| `source_url` | 情報の根拠（HTTPS） |
| `rights_status` | `permitted`（利用許可のあるソース）または `self_recorded`（自分が権利を持つ記録） |
| `line_id` | 事前に分かったライン識別子。同じラインは同じ値 |
| `line_position` | そのライン内での位置（1から始める） |
| `rating` | 出走表から得たレース前の競走得点（例、直近期間の平均） |
| `recent_win_rate` | 出走前に確定していた近走の1着率（0〜1） |
| `recent_top2_rate` | 出走前に確定していた近走の2着以内率（0〜1） |
| `recent_top3_rate` | 出走前に確定していた近走の3着以内率（0〜1） |
| `age` | 出走日時点の年齢 |

**注意：** この6特徴量は最小のデータ契約であり、十分な競輪予測性能を保証しません。`rights_status` はユーザー申告であり、許諾の法的検証を行うものではありません。

### 判定
- 時刻の事後逆流（`observed >= deadline`）、失格・同着により確定着順が1種類に定まらないレース、車番欠落、出典不備、重複した選手、利用許諾未確認などは**受け入れない**。
- 勝者は `exports/results_3rentan.csv` の `winning_combination` と照合するだけ。確定オッズ、人気順位、結果払い戻しを事前特徴量へ混入させません。
- 500レース、30日以上を**最低限の入力規模のゲート**として表示しますが、ゲート通過で予測AIや通知を許可することはありません。独立した時系列ホールドアウトと確率校正が必要です。
- 既存の `paper_trading/verified_models.json` は空のままです。購入候補としてのDiscord通知は停止したまま維持します。
