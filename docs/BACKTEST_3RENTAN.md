# 実際の払戻による3連単バックテスト（研究用）

`tools/backtest_3rentan.py` は**事前に保存した予測確率・締切前オッズ・確定結果**を時系列順に照合し、100円を1レースにつき最大1点だけ仮想投票した場合の過去収支を計算します。Webアクセス、OpenAI API、Discord投稿、実際の投票はありません。

## 現在のローカルでは何が不足しているか

- `local_data/odds_snapshots/<race_id>.jsonl` ：締切前に保存されたオッズ。松山1Rは実機で保存済み。
- `local_data/models/<race_id>_top3.json` ：**オッズを確認する前に実モデルが生成した**全210/336/504組の着順同時確率。実機で有効なものはまだ未確認。
- `exports/results_3rentan.csv` ：実際の確定結果・100円払戻金。保存済み松山1Rと一致するレースIDの行があるか別途確認が必要。

実データが足りなければ `NOT_READY_NO_SETTLEABLE_POINT_IN_TIME_BETS` となります。**これはプログラムの故障ではなく、未来の確定結果から予想を作るのを拒否している状態です。**

## Windowsで実行

```cmd
py -3 tools\backtest_3rentan.py --output local_data\backtests\3rentan.json
```

出力の主な項目：

- `eligible_bet_count` ：検証に使えたレース数（最低500件を満たすとは限りません）。
- `hits`／`hit_rate` ：的中回数と率。
- `notional_stake_yen` ：仮想投票総額。
- `settled_actual_payout_yen` ：結果CSVの**確定100円払戻金**で計算した合計払戻。
- `realized_return_ratio` ：合計払戻÷合計投票。1.30が130%。
- `maximum_drawdown_yen` ：仮想累積損益の最大ドローダウン。
- `rejected_counts` ：何が足りず検証対象にできなかったか。
- `selections` ：選ばれた買い目の研究用履歴（`local_data/` にのみ保存）。

予測確率×**その時点のオッズ**×0.75が1.30以上の候補があれば、最も高い1点を選びます。ただし収益の計算には事前オッズを使いません。**実際に確定した3連単100円払戻**だけを使用します。複数の事前オッズ記録があれば、予測生成後の**最初に利用可能な記録**を選び、あとから「一番有利だった時刻」を選びません。

結果の紐付けは、結果CSVの正規レースIDまたは出典URLに含まれる **Kドリームスの数字レースID** が完全一致する場合に限定します。同着・返還・中止・無効結果・重複結果・払い戻し不足・明らかな整合不良は除外。サイトが提示した更新時刻と観測時刻の差が10分を超えたデータも除外します。

**注意：** 過去に人気だった買い目だけを後付けした場合、実際の予測タイムスタンプに見せかけてはいけません。時系列を満たす自己申告時刻だけでは後付け予測を完全に排除できないため、信頼できる運用には予測の改変不能な自動記録や前向き仮想投票が必要です。

## 7賭式の収益検証がまだできない理由

現在の確定結果CSVは**3連単の払戻が中心**で、2車単、3連複、ワイド、2枠単、2枠複、2車複の各買い目の確定払戻を揃えていません。3連単の払戻を他の賭式へ流用することは不正確なので行いません。将来、払戻・返還・同着情報を揃えた正式な結果CSVを追加した場合、賭式別に拡張します。

**バックテストの回収率は将来の回収率の保証になりません。** モデルのチューニングで結果を見ていればテストが汚染されます。手数料、販売停止、払戻訂正、遅延など現実の要因も未検証です。
