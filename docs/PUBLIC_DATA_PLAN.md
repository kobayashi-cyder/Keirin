# 競輪公開情報の収集・分析データ設計

更新: 2026-11-01。対象は原則2020-01-01以降、開催日 × 全会場 × 全レース。
「公開されている」と「第三者がGitHubで一括再配布してよい」は別。許諾不明の外部サイト全文・画像・動画・データベースの大規模複製は行わず、出典リンクと取得可否を管理する。

## 今回追加した分析用データ

`python3 tools/build_analysis_tables.py` は、既にGitHubに保存されている `data/*.csv` から、**ネットワークアクセスなし**で次の3つを再計算する。

| ファイル | 1行の意味 | 重要な列 |
| --- | --- | --- |
| `exports/results_3rentan.csv` | 3連単の的中組番と払戻。1着同着等は同レース複数行 | race_id, winning_combination, payout_per_100yen, winning_final_odds, popularity_rank, source_urls, source_files |
| `exports/odds_3rentan.csv` | 既存収集済みの人気順位別3連単オッズ1点 | race_id, rank, combination, odds_multiplier, odds_status, source_timestamp_jst, source_urls, source_files |
| `exports/source_manifest.csv` | 元CSVごとの件数・SHA-256・出典リンク付与率 | path, kind, rows, unique_races, sha256, rows_with_source_url |

全列はUTF-8 CSV。出典が複数あれば `|` 区切り。記録のない出典・オッズ時刻・人気順位は空欄または unknown とし、推定値で埋めない。
`winning_final_odds` は結果判明後の100円払戻金を100で割った倍率であり、締切前に観測した全買い目オッズの代替には**ならない**。

出力は元CSVを変更しない。元ファイルに同一事実が重複している場合は統合し、払戻金・順位・倍率・組番が矛盾すればエラーにする。すべての出典の正確性を保証するものではない。

## 今後の収録範囲（優先順位）

1. **日付・開催**: 開催／中止、会場、開催区分、レース番号、発走予定・実際時刻、出典、欠損日。開催一覧未確認日は「開催なし」としない。
2. **結果・払戻**: 車番別確定着順、失格・落車・棄権・欠車、同着、返還・中止、3連単全的中組番、払戻金、人気順位。
3. **オッズ**: 3連単全買い目（少なくとも人気上位100点）、オッズ観測時刻（JST）、締切前／最終確定の区別、車券種（2車単、2車複、3連複、ワイド等）、返還後調整。**結果の払戻倍率と個別オッズは別データ**。
4. **出走表・選手**: 出走車番、選手ID、級班・年齢・所属、競走得点、直近成績、脚質、欠場、並び／ライン（観測時点を保持）。
5. **条件**: バンク・周長、開催グレード、レース種別、天候・風・路面、参加車数、売上・投票総数（公開かつ再利用許可のあるもの）。
6. **分析用派生情報**: 人気順位、的中フラグ、事前確率（推定）、学習・検証・試験期間、データ品質指標と欠損率。

各レコードの基本キーは `race_id=YYYYMMDD_venue_slug_RR`。選手・オッズ・時系列の表は追加の選手ID／組番／観測日時で一意にする。データ出典と利用許諾ステータスを付随させ、将来のソース更新で上書きしない。

## 公開元と権利の確認

- KEIRIN.JP 開催日程: https://www.keirin.jp/pc/raceschedule
- KEIRIN.JP グレードレース: https://keirin.jp/pc/graderaceschedule?scyy=2026
- KEIRIN.JP サイトポリシー: https://keirin.jp/pc/dfw/portal/guest/policy/index.html （複製・転用等は原則制限）
- 楽天Kドリームス 日別開催一覧: https://keirin.kdreams.jp/kaisai/2026/10/31/
- 楽天Kドリームス サイト利用条件: https://keirin.kdreams.jp/info/sitepolicy/ （無断転載・コピー禁止）

**取得前チェック**: 許諾・契約/API条件・robots・レート制限・個人情報・データの再配布可否。権利未確認ならURL、検証状況、集計メタデータのみを記録する。401/403/429等や認証画面が出れば停止し、回避しない。

## 残件を実際に減らす運用

`data/coverage_summary.json`、`data/pending_races.csv`、`reports/coverage.md` を取得前後で比較する。既知の残件から先に収集し、権利上収録不能なら代替の許諾可能ソースを調べる。対象が増えることで分母だけ増える場合は、結果取得の進捗として報告しない。
`data/public_sources.csv` は「発見した外部情報源と再利用条件」のカタログであり、そこに掲載しただけでは収集許可済みではない。

## モデルを評価する際の注意

Top100のみで全買い目に対する確率を正規化しない。人気上位の欠損や事後確定オッズを締切前データとして扱わない。日付を混ぜたランダム分割による情報漏えいを避け、原則、過去→未来の時系列で評価する。期待値や回収率は観測時点の車券価格・払戻と分けて再計算する。
